# Web API

## Basics

### What is Web API?

<!-- level: beginner -->

API stands for **Application Programming Interface**.

ASP.NET Web API is a Microsoft framework for building HTTP services easily. It is an ideal platform for building RESTful applications on .NET.

### What is the difference between ASP.NET Web API and WCF? Why choose Web API over WCF?

<!-- level: intermediate -->

| Web API | WCF |
| --- | --- |
| Supports content negotiation | No content negotiation |
| RESTful services | SOAP-based services |
| Supports MVC features such as routing and model binding | Does not support MVC features |
| Token-based authentication | – |

### What are SOAP-based services?

<!-- level: beginner -->

SOAP (Simple Object Access Protocol) services mostly work over HTTP using RPC (Remote Procedure Call), and exchange messages in XML format.

## HTTP methods

### Why do we need HTTP methods?

<!-- level: beginner -->

- **GET** – return a resource
- **POST** – create a new resource
- **PUT** – update (replace) a resource
- **PATCH** – partially update a resource
- **DELETE** – delete a resource

### What is the difference between GET and POST?

<!-- level: beginner -->

| | GET | POST |
| --- | --- | --- |
| Parameters | In the URL (query string) | In the request body |
| Security | Less secure (visible in URL, history and logs) | More secure |
| Capacity | URL length limit (about 2048 characters) | Much larger |
| Data type | ASCII only | Any type, including binary |

### What is the difference between POST and PUT?

<!-- level: intermediate -->

- **Idempotent** – running the request multiple times leaves the server in the same state
- **Non-idempotent** – running the request multiple times changes the state each time

| | Create | Update | Who controls the ID |
| --- | --- | --- | --- |
| Idempotent | PUT (if the ID is controlled by the client) | PUT | Client |
| Non-idempotent | POST (if the ID is generated by the server) | – | Server |

> **Interview tip:** The key word here is *idempotent*. Sending the same PUT twice leaves the resource unchanged; sending the same POST twice usually creates two resources.

### What is the difference between PUT and PATCH?

<!-- level: intermediate -->

| | PUT | PATCH |
| --- | --- | --- |
| Update | Full update – send the whole resource | Partial update – send only the changed fields |

PUT request to `http://localhost/Product/1001`:

```json
{
    "Name": "Amit",
    "Amount": 10000
}
```

PATCH request to `http://localhost/Product/1001`:

```json
{
    "Name": "Amit"
}
```

## Responses and binding

### How do you return a PDF file from a Web API?

<!-- level: intermediate -->

Return the file bytes with the `application/pdf` content type. In ASP.NET Core, use `File()`:

```csharp
[HttpGet("{id}/pdf")]
public IActionResult GetPdf(int id)
{
    byte[] bytes = _reportService.GetPdf(id);
    return File(bytes, "application/pdf", "report.pdf");
}
```

### Why use `IHttpActionResult` instead of `HttpResponseMessage`?

<!-- level: intermediate -->

- Cleaner code – helpers such as `Ok()`, `NotFound()` and `BadRequest()` replace building the response by hand
- Easier unit testing – you assert on the result type instead of parsing an HTTP message
- The response logic can be reused in your own `IHttpActionResult` classes

In ASP.NET Core the equivalent is `IActionResult` / `ActionResult<T>`.

### Why are the `FromBody` and `FromUri` attributes needed?

<!-- level: intermediate -->

They override Web API's default parameter binding:

- By default, simple types (`int`, `string`, `DateTime`) are read from the URI and complex types from the request body
- `[FromBody]` forces a parameter to be read from the request body
- `[FromUri]` forces a complex type to be read from the URI (query string). In ASP.NET Core this is `[FromQuery]` / `[FromRoute]`.

```csharp
public IHttpActionResult Get([FromUri] SearchFilter filter) { ... }
public IHttpActionResult Post([FromBody] string name) { ... }
```

### What is ASP.NET Web API OData?

<!-- level: advanced -->

OData (Open Data Protocol) is a standard for building queryable REST APIs. With OData, clients can filter, sort, page and shape the data through the URL:

```text
GET /odata/Products?$filter=Price gt 100&$orderby=Name&$top=10&$select=Name,Price
```

## Security

### What exactly is OAuth (Open Authorization)?

<!-- level: intermediate -->

OAuth 2.0 is an **authorisation** framework. It lets an application access resources on behalf of a user, without the user sharing their password with that application. The authorisation server issues an **access token**, which the client sends to the API (usually as a `Bearer` token).

### What is the difference between OpenID and OAuth?

<!-- level: intermediate -->

| | OAuth 2.0 | OpenID Connect |
| --- | --- | --- |
| Purpose | Authorisation – *what can you access?* | Authentication – *who are you?* |
| Token | Access token | ID token (JWT) plus access token |
| Built on | – | Built on top of OAuth 2.0 |

### How do you implement API-to-API authentication?

<!-- level: advanced -->

- **OAuth 2.0 client credentials flow** – the calling service gets a token from the identity provider (e.g. Azure AD) using its client ID and secret, and sends it as a Bearer token (most common)
- **API keys** – a shared secret sent in a request header
- **Mutual TLS (mTLS)** – both services authenticate each other with certificates
- **Managed identities** – on Azure, the platform supplies the credentials so no secret is stored

### What is CORS (Cross-Origin Resource Sharing)?

<!-- level: intermediate -->

Browsers block JavaScript from calling an API on a different origin (domain, scheme or port) by default. CORS lets the API tell the browser which origins, methods and headers are allowed.

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowWebApp", policy =>
        policy.WithOrigins("https://myapp.com")
              .AllowAnyHeader()
              .AllowAnyMethod());
});

app.UseCors("AllowWebApp");
```

## Hosting

### What is OWIN self-hosting?

<!-- level: advanced -->

OWIN (Open Web Interface for .NET) defines a standard interface between .NET web applications and web servers. It decouples the application from IIS, so a Web API can be **self-hosted** in a console application or Windows service. In ASP.NET Core, the built-in Kestrel server replaces OWIN self-hosting.
